# SimTrail — The open simulation project manager

SimTrail is a local-first, open-source desktop application for organizing
simulation projects, tracking runs, comparing captured inputs and results, and
preserving engineering decisions. Its first live integration is Ansys
Workbench; the core data model is intended to remain solver-neutral.

> **Technical preview:** SimTrail 0.1 is suitable for demonstrations and
> controlled evaluation. It is not yet an audit-qualified system of record.
> Review the [known limitations](docs/KNOWN_LIMITATIONS.md) before using it on
> engineering work.

SimTrail is independent of Ansys, Inc. and is not sponsored by or affiliated
with Ansys.

## What it does

- Captures Workbench systems into a local simulation run register.
- Joins extracted inputs and headline results with analyst context.
- Compares any two captured runs in engineering language.
- Searches, filters, sorts, and exports project history.
- Keeps model files and the SQLite register on the user's machine.
- Supports controlled Workbench metadata writes for system names and notes.

## Run it

Python 3.11+ is required. Ansys is optional for exploring the demo dataset and
the solver-neutral project workflow; it is only required for the live Workbench
integration.

```powershell
python -m pip install -e .
python main.py
```

On first launch, the app creates a local SQLite database and adds a realistic
demo dataset. To start with an empty database:

```powershell
python main.py --empty --db .\.simtrail\empty.db
```

## MVP workflow

1. Browse, search, filter, sort, resize, and choose visible columns in the run register.
2. Select any row to inspect engineering context, all captured inputs, and all captured results.
3. Ctrl-click two rows, then choose **Compare selected** for a human-readable diff.
4. Export either the filtered register or a comparison to `.xlsx`.
5. Use **Capture snapshot** to import a JSON snapshot or recursively scan a project folder.

Use **Save project** to create a portable `*.simtrail-project.json` containing every run in the selected project. Reopen it later from **Capture snapshot → Open saved SimTrail project**. Exact snapshots are merged, while systems with changed inputs/results are retained as new historical runs.

**Clear everything** removes all runs from the local SQLite register after confirmation. It does not delete Workbench files or saved SimTrail project files, and cleared demo data does not return on the next launch.

## Workbench project scan

The **Workbench scan** page discovers every system in an open Workbench project, suggests a reference analysis, compares captured fields, accepts per-system analyst context, and imports selected systems into the run register.

Install the persistent ACT connector once:

1. Close Workbench.
2. Run `.\ansys_extension\install_extension.ps1 -AnsysVersion v261`, changing `v261` to the installed Ansys release.
3. Restart Workbench and enable **SimTrailConnector** in **Extensions → Manage Extensions**. Select its load-by-default option when available.
4. Start SimTrail and open the target Workbench project in either order. The connector retries automatically.
5. Open **Workbench scan**. A green connection pill identifies the live project and a scan starts automatically.
6. Select a system to rename it or synchronize its Workbench note. Workbench remains unsaved until the analyst chooses to save it.
7. Optionally choose **Extract existing results**. This opens each selected Mechanical model as needed,
   reads scalar values from existing evaluated result objects, and does not solve or evaluate results.
8. Confirm the suggested reference, add per-system analyst context, and import selected systems.

The connector uses the local Windows named pipe `SimTrail.Workbench.v1`; it creates no network listener. Heartbeats detect disconnects, and Workbench Project Schematic callbacks trigger a debounced rescan after create, update, refresh, duplicate, source-change, delete, load, or save actions. Rename uses an expected-current-name check to prevent overwriting a concurrent change.

When Workbench is running without the connector, SimTrail reports **Workbench detected · connector unavailable**. When the extension is connected, the pipe handshake is authoritative and supplies the project path, version, and process identity.

The inventory includes project topology, cell states, system notes, and exposed Workbench input/output parameters. The manual result extractor additionally reads `Minimum`, `Maximum`, `Average`, and `Total` from existing evaluated Mechanical result objects. Mechanical may start in hidden mode and use a Mechanical license while this command runs. Unevaluated results are reported but are never evaluated automatically.

You can test the screen without Ansys using **Load example**, or load a saved `*.simtrail-workbench.json` file generated by `ansys_bridge/workbench_inventory.wbjn`.

The connector does not modify Mechanical model physics or invoke a solve. Result extraction can start a Mechanical session and therefore may use a Mechanical license. Renaming and notes mark Workbench metadata as changed; saving remains under user control.

## Snapshot contract

The temporary extractor boundary is a JSON file ending in `.simtrail.json`. See [`examples/bracket-run.simtrail.json`](examples/bracket-run.simtrail.json). Required fields are `name`, `project`, `inputs`, and `results`; the two latter values must be JSON objects.

```json
{
  "name": "Run 012 · refined mesh",
  "project": "Actuator bracket",
  "analyst": "A. Engineer",
  "created_at": "2026-07-16T10:30:00",
  "status": "Solved",
  "solver": "Ansys Mechanical 2026 R1",
  "inputs": {
    "Material": "Al 7075-T6",
    "Global mesh size": "1.2 mm"
  },
  "results": {
    "Max equivalent stress": "279 MPa",
    "Minimum safety factor": 1.79
  }
}
```

## Architecture

- `simtrail/models.py` — solver-neutral run and diff model
- `simtrail/database.py` — local SQLite repository
- `simtrail/importers.py` — version-independent snapshot boundary
- `simtrail/exporters.py` — styled Excel register/comparison exports
- `simtrail/live_connection.py` — persistent named-pipe server and command protocol
- `simtrail/ui.py` — PySide6 run table, detail panel, and diff dialog
- `simtrail/app.py` — application startup and data location
- `ansys_extension/SimTrailConnector` — Workbench ACT client and lifecycle callbacks

The project roadmap prioritizes immutable provenance and connector reliability
before additional solver integrations. See [ROADMAP.md](ROADMAP.md) and the
[architecture overview](docs/ARCHITECTURE.md).

## Windows test package

The portable build does not require Python:

1. Download or copy `dist\SimTrail-TestKit-0.1.0.zip`.
2. Extract the entire ZIP to a writable local folder.
3. Run `SimTrail.exe`.
4. To test the live Workbench connection, close Workbench and run
   `connector\install_extension.ps1 -AnsysVersion v242` from PowerShell.
   Change `v242` to match the installed Ansys release.
5. Reopen Workbench, enable **SimTrailConnector** in
   **Extensions → Manage Extensions**, and then start SimTrail.

Windows SmartScreen can warn because this test executable is not code-signed.
The local run database remains outside the executable in the user's application
data folder, so replacing the EXE does not erase imported runs.

To rebuild the portable executable and test kit:

```powershell
.\packaging\build.ps1
```

`packaging\SimTrail.iss` is also provided for producing a conventional per-user
installer with Inno Setup. Compile it with `ISCC.exe packaging\SimTrail.iss`
after installing Inno Setup.
